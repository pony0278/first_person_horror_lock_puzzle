## 1. 產品定位

### 一句話概念

> 怪物正在逼近，而你不知道還剩多少時間。

### 核心體驗支柱

1. **隱藏的時限**：沒有任何倒數 UI，唯一的時間資訊是怪物離你多近。
2. **自願的恐懼**：回頭完全免費，但你可能看到牠已經在你身後。
3. **可推理的門鎖**：假針必須靠觀察分辨，不能靠運氣。
4. **上下分層資訊**：下方給「感覺」，上方給「事實」。
5. **短局重玩**：單局約 90 秒，死亡到重開 1.5 秒。

### 這款遊戲不是什麼

- 不是規劃逃生路線的 roguelite（v1 方向，已否決）。
- 不是注意力管理遊戲（回頭免費之後，取捨不存在）。
- 不是 Steam 產品（三扇門、兩分鐘，規模不符買斷制期待）。

## 2. 平台約束（硬性）

來自 CrazyGames 的規範，全部視為不可協商：

- **分級**：PEGI 12，受眾 13 歲以上。無血腥、無寫實五官特寫。
- **初始下載**：≤ 20MB（進入手機首頁的門檻）。
- **畫面**：16:9 響應式，桌機與手機皆可玩，最低 30 FPS、目標 60 FPS。
- **進入速度**：玩家一進來就在 gameplay 裡，最多容許一次點擊。
- **裝置適配**：手機需提供觸控操作，UI 文案隨裝置切換。

### 已知技術風險（第一週內驗證）

| 風險 | 說明 | 應對 |
| --- | --- | --- |
| iOS Safari WebGL 2.0 | 有已知問題，且手機流量佔比高 | 真機測試，不用模擬器 |
| WebGL context loss | 切分頁／退背景可能遺失 context | 實作恢復流程，避免黑畫面 |
| Web Audio 延遲 80～150ms | 節奏類玩法不可靠 | 已砍除節奏鎖；聲音只做加速器 |
| Vibration API | iOS Safari 不支援 | 僅作為 Android 的加分頻道 |

## 3. 核心循環

```text
關卡開始
→ 第一人稱奔跑約 3 秒（可側頭：找提示、撿能力）
→ 抵達逃生門
→ 隱藏計時器啟動
→ 撬鎖（下方操作，上方同步）
→ 玩家可隨時免費回頭確認怪物距離
→ 完成解謎 → 鎖芯轉滿 → 開門 → 關門
→ 下一扇門（共 3 扇）
```

### 時間預算

| 階段 | 時間 |
| --- | --- |
| 奔跑與情報蒐集 | 3 秒 |
| 門前解謎（隱藏時限） | 18～25 秒 |
| 開門與關門演出 | 2～4 秒 |
| 單扇門總長 | 約 25～30 秒 |
| **單局總長** | **約 90 秒** |

## 4. 輸入方案

### 手機（16:9 橫向）

```text
┌─────────────────────────────────────────┐
│                                         │
│   上方 65～70%：第一人稱視野、工具、鎖芯    │
│                                         │
├─────────────────────────────────────────┤
│   下方 30～35%：撞針解謎操作區             │
└─────────────────────────────────────────┘
```

| 手勢 | 效果 |
| --- | --- |
| 下方按住＋橫向拖曳 | 工具在撞針之間移動 |
| 下方向上推 | 頂起當前撞針 |
| 下方向下大幅拖曳 | 全部撞針落下（約 1 秒） |
| 下方對準單針向下推 | 只洩掉該支（約 0.6 秒） |
| 上方按住＋左右拖曳 | 側頭觀察 |
| 上方按住＋向下拖曳 | 回頭觀察 |
| 放開 | 鏡頭回彈至門鎖 |

撬鎖全程不需要放開手指，整組鎖是一個連續動作。

### 桌機（同一套規則）

```text
滑鼠在下方區       → 撬鎖（同上）
按住 A / D         → 側頭左 / 右
按住 S             → 回頭
放開               → 回彈
```

### 洩壓機制（必要）

玩家識破假針後必須能放下它，否則會卡死到超時。兩種洩壓方式讓技巧差異自然浮現：新手整組重來，熟練玩家精準洩單支。

## 5. 觀察系統

**所有觀察都是免費的**——不損失撞針、不損失進度。唯一的成本是機會成本：鏡頭轉走時門鎖不在畫面上，因此下方停止接受輸入，而時間繼續流逝。

| 動作 | 角度 | 內容 | 下方輸入 |
| --- | --- | --- | --- |
| 側頭 | 45° | 環境氛圍、門邊殘缺提示 | 停止 |
| 回頭 | 180° | 怪物距離 | 停止 |

### 為什麼不需要限制觀察次數

一直看就一直沒在解鎖，時間到就死。自我約束天然成立。

### 驚嚇反應（非懲罰）

回頭時若怪物已在近距離，播放短促的生理反應：鏡頭猛震、工具滑落、呼吸急促。這不是規則，是角色反應，但效果上玩家會遲疑下一次要不要看。

## 6. 計時器與怪物模型

### 第一原則：怪物必須誠實

怪物的位置是計時器的唯一顯示。因此**橡皮筋機制一律禁止**——在唯一的資訊管道上說謊，玩家長期會感覺到而說不出原因。

基礎速度固定，只有玩家自己的錯誤能改變它。

### 隨機性放在曲線形狀，總時間守恆

```text
等速型   ████████████████████     平穩逼近，最好預測
潛伏型   ███░░░░░░░░████████████  前段幾乎不動，後段暴衝
壓迫型   ████████████░░░░░░░███   一開場就近，中段停滯，最後補上
```

三種都在時限末抵達，但心理曲線完全不同。玩家永遠有相同的秒數，只是不知道那段時間長什麼形狀。

**副作用（刻意的）**：單次回頭無法換算剩餘時間。要知道還剩多少，必須看兩次比較距離變化率。回頭因此從一次性確認變成持續取樣行為。

### 錯誤懲罰

- 單次錯誤：摩擦聲＋約 0.4 秒回彈延遲。
- **連續錯 3 次**：怪物**瞬間前進一段距離**（不是提速）。

瞬移是可見的震撼，玩家下次回頭會發現距離對不上預期。提速是隱形的，只會讓人覺得莫名其妙。

### 極限成功窗口

怪物抵達門口後給約 1 秒的抓取前搖。玩家若在此窗口內完成最後一支撞針，觸發極限成功：門在怪物手伸進來的瞬間關上，所有追逐聲突然停止，只剩喘息。

實作成本低，情緒回報最高，且是社群分享片段的主要來源。

## 7. 門鎖設計

### 唯一鎖型：撬鎖／撞針

變化來自**規則變體**，不是新的介面：

| 變體 | 機制 |
| --- | --- |
| 基礎 | 4 針、1 假針 |
| 滑落針 | 某支固定後會慢慢滑下，必須最後處理 |
| 雙生針 | 兩支必須連續頂起，中間不能碰其他針 |
| 多假針 | 2 支假針 |
| 六針 | 量的擴張 |

全部共用同一套 UI、動畫、提示語彙。玩家不需重新學習。

### 撞針的三種狀態

```text
錯的針  → 推到約 40% 高度就頂住，推不上去
對的針  → 順暢上到 100%，「喀」一聲固定
假的針  → 順暢上到 100%、固定住 —— 但上方鎖芯不轉
```

前兩者靠**針的高度**即可分辨，完全不依賴聲音。

### 未來的第二種鎖（F3 以後）

若要加入第二種鎖，選擇標準是**操作維度互補**。撬鎖的本質是「序列」，因此第二種鎖不該也是序列（v1 的旋轉密碼鎖仍是序列記憶，體感雷同）。

建議方向：**併發型**——三個滑塊必須同時維持在指定位置，但各自會漂移，玩家必須輪流去救。水平排列完美適配寬扁操作區，且「同時維持多件事」與怪物逼近的注意力壓力疊加良好。

## 8. 提示系統

### 符號：顏色＋形狀，不用數字

```text
撞針：  ● 紅圓   ■ 藍方   ▲ 黃三角   ◆ 綠菱形   （位置每局隨機）
牆上：  ▲ → ● → ◆ → ■
```

- 不需要「數針」的轉換成本，1 秒內可讀。
- 零文字，不需在地化。
- 形狀作為色盲輔助，成本極低。

**資訊單位上限：4 個。**

### 三層資訊路徑

| 路徑 | 取得方式 | 完整度 | 解題時間 |
| --- | --- | --- | --- |
| 上策 | 奔跑時看到牆面 | 完整順序 | 約 8 秒 |
| 中策 | 門邊側頭找殘留 | **部分**（血跡糊掉、只剩前兩位或只標出假針） | 約 12 秒 |
| 下策 | 純暴力試探 | 無 | 約 16 秒 |

中策的殘缺是刻意的：既給漏看的玩家救命繩，又不至於讓人放棄在奔跑階段讀提示。

### 目標倍率

**有提示 : 無提示 ≈ 1 : 2。** 漏看提示不會直接死，但會失去所有容錯空間。

新手在漏看提示下的完成率目標 50～60%。低於 30% 會勸退，高於 80% 表示提示不值錢。

### 隱性教學（不做 tutorial UI）

```text
第 1 局    提示在正前方、字很大    → 建立「牆上有東西」的認知
第 2 局    提示略偏一側            → 開始需要側頭
第 3 局起  提示位置隨機            → 側頭成為習慣
```

## 9. 回饋與上下同步

### 分層原則

```text
下方解謎區  →  觸覺層級：這一下感覺對了嗎
上方實體鎖  →  事實層級：我到底固定了幾支
```

鎖芯採**累進角度**：每固定一支真撞針轉動約 8～10°，遇到假針完全不動。

| 事件 | 下方 | 上方 | 聲音 |
| --- | --- | --- | --- |
| 真固定 | 撞針停住、微弱亮起 | 鎖芯累進轉一格 | 清脆的喀 |
| 假固定 | 撞針停住、微弱亮起（**幾乎相同**） | 鎖芯**不動** | 略悶的喀 |
| 錯誤 | 撞針回彈 | 工具震動、手部晃動 | 摩擦聲 |

**下方無法分辨真假，上方可以。** 玩家必須主動比對鎖芯——而在壓力下多數人不會每支都比對。提示的價值就是讓你不需要比對。

### 調校要點

- 鎖芯角度差控制在 8～10°。做成 45° 等於直接標答案。
- **不設「接近正確」層級**：撞針鎖是離散的，一支針只有固定／未固定兩種狀態，沒有「接近」的語意。
- 單次錯誤不給重罰，只有連續 3 次才觸發。暴力試探是設計允許的路徑。

### 上方區域承擔資訊職責

橫向拖曳選針時手指會蓋住當前撞針，因此「目前選中哪一支」必須顯示在針的上方或同步至上方實體鎖。上下同步不是美術訴求，是機械需求。

### 靜音檢查（全部通過）

| 事件 | 靜音可辨識 |
| --- | --- |
| 真固定 | 鎖芯轉動 |
| 假固定 | 鎖芯不動 |
| 錯誤 | 撞針回彈＋手部晃動 |
| 連續錯誤 | 怪物瞬移＋暗角收縮 |

**聲音是加速器，不是必需品。**

## 10. 恐怖情緒工程

### 升壓綁距離，不綁秒數

曲線隨機化之後，秒數會失效（潛伏型的第 5 秒和壓迫型的第 5 秒是完全不同的處境）。

| 距離 | 表現 |
| --- | --- |
| 100～75% | 遠處腳步、門框輕微震動 |
| 75～50% | 走廊燈逐盞熄滅、工具開始晃 |
| 50～25% | 影子掠過牆面與門縫、呼吸聲進入 |
| 25～10% | 暗角急速收縮、鎖區邊緣失焦 |
| 10～0% | 怪物進入回頭視野的清晰範圍 |

綁距離的好處：升壓自動繼承曲線個性，不需為三種曲線各做一套演出。

### 暗角不可連續

50% 之前暗角幾乎不動，之後才明顯收縮。連續變化會洩漏精確距離，讓回頭失去意義。前半段玩家必須回頭才知道，後半段知道「快了」但仍不知還剩幾秒。

### Jump scare：一次都不做

最好的驚嚇來源是**玩家自己按下回頭，發現牠比預期近得多**——玩家觸發、有因果、時機每局不同、零額外美術。彈出式驚嚇只會稀釋它。

### PEGI 12 下的驚嚇手法

- 突然填滿畫面的**剪影**，不是有五官的臉。
- 動作的速度差（緩慢→瞬移）。
- 死亡瞬間快速切黑，不停留在怪物身上。

### 清晰度分層（保值）

```text
距離 > 10%   永遠是剪影
距離 < 10%   才顯出輪廓細節（依然無五官）
```

玩家大部分時間只看到剪影，「看清楚」的瞬間很少發生，因此不會鈍化。短局遊戲死亡頻繁，任何重複播放的驚嚇撐不過 5 次。

## 11. 難度與局結構

### 三扇門

由「可接受的損失」決定，不是由內容量決定。20 秒循環的遊戲，5 門局（150 秒）的死亡損失過重，而第 5 門恰好最容易死。

```text
門 1   4 針、1 假針、25 秒、等速型         → 隱性教學
門 2   5 針、1 假針＋滑落針、20 秒、曲線隨機  → 規則變化
門 3   6 針、2 假針、18 秒、曲線隨機        → 全開
```

**時間只縮 28%，複雜度大幅上升。** 時間壓縮是輔助軸，一旦用掉就沒得再用；規則變化才是主軸。

隱藏計時器讓玩家察覺不到時限在縮短，只會感覺「這隻怪物比較兇」——而怪物移動仍然誠實，敘事上完全成立。

### 難度池，不用純隨機

```text
門 1 的配置池 → 只放簡單配置
門 2 的配置池 → 中等
門 3 的配置池 → 困難
```

純隨機會產生兩種傷害留存的極端：門 1 抽到六針雙假針（新手勸退），或門 3 抽到四針無假針（高手被浪費時間）。

固定種子留給 F4 的每日挑戰。

### 門後能力：塞進奔跑階段，不開選單

恐怖遊戲最怕停下來。玩家剛從門縫逃出來、心跳未平，彈一個三選一 UI 會讓那口氣洩掉。

```text
關門 → 轉身 → 開始奔跑
       走廊上散落三樣東西
       側頭 + 跑過去碰到哪個就拿哪個
       沒碰到就沒有
```

零 UI、不打斷節奏，而且選擇本身帶時間壓力（只有 3 秒，還要同時找提示）。

**能力清單（3～4 種，全部改變容錯而非加數值）：**

- 這扇門少一支假針
- 門邊提示完整顯示（不再殘缺）
- 怪物起始距離增加
- 洩壓速度加倍

## 12. 失敗與重試

### 整局重來

回到當前門會殺掉張力——玩家知道死了沒差就不會怕。整局重來只有在單局夠短時成立，這正是選 3 門的理由。

```text
損失 90 秒進度 + 1.5 秒等待 → 立刻回到門 1
```

### 只講一個原因

失敗可能有多重成因，但結算只點名**損失時間最多**的那一項：

```text
「你沒有看到牆上的順序。」
```

一句話，不解釋，不給建議。列三條會稀釋教訓。

### 重試速度

- 死亡演出上限 1.5 秒。
- 建議不放重試按鈕，直接自動重開。

## 13. 技術架構

```text
上方 65～70%   Three.js：走廊、光影、怪物、工具、鎖芯
下方 30～35%   DOM 或 Canvas 2D：撞針解謎介面
               共用一份遊戲狀態物件，上下同步由資料綁定達成
```

### 選型理由

- 下方是平面 UI，用 3D 只是自找麻煩；DOM 可直接取得觸控事件與 CSS 動畫。
- 上方需要真 3D 的只有兩件事：轉頭的連續鏡頭旋轉、怪物由遠而近的距離感。這兩件事用 2D 假 3D 做非常痛苦。
- Three.js 核心經 tree-shaking 後約數百 KB，遠低於任何引擎 runtime。

### 為何不用 Godot 4

- Web 匯出即使精簡 asset pack 仍在 25MB 左右，3D 專案通常 30～100MB。光引擎 baseline 就吃掉全部 20MB 預算。
- Web 匯出僅支援 Compatibility 渲染（WebGL 2.0），Forward+ 與 Mobile 渲染器不可用。
- 手機端記憶體上限更緊，iOS Safari 需單獨測試。

### 架構要求（為未來的 Steam 版）

用 TypeScript，將遊戲邏輯（撞針狀態機、計時器、難度池）與渲染層分離，之後移植時邏輯層可整包帶走。

**除此之外不為 Steam 做任何額外功能**——這是最容易吃掉 F0 時程的陷阱。

## 14. 美術與資產預算

```text
上方區域的模型 + 材質   ≤ 2MB
初始下載總量           ≤ 20MB
風格                  極低多邊形、無貼圖、純光照驅動
```

無貼圖不是妥協，是這個題材的正解——恐怖來自看不清楚。低多邊形的塊狀手在這個風格下完全成立。

### 動畫幾乎全部可程序化

| 狀態 | 實作 |
| --- | --- |
| 工具橫向移動 | 位置綁定選中的針索引 |
| 上推 | 工具尖端位移＋旋轉 |
| 頂住失敗 | 小幅回彈 |
| 固定成功 | 鎖芯轉 8～10° |
| 洩壓 | 工具下拉 |
| 開門 | **唯一需要製作的動畫** |
| 死亡 | 快速切黑 |

**F0 完全不做手**——手的 rig 與 skinning 是最貴的單項，而工具位移已傳達 100% 必要資訊。F1 加手時用程序化 IK（手腕跟著工具走，2～3 個關節），所有變體自動共用。

### 資產壓縮

- 音效用 OGG Vorbis，音樂用 MP3。
- 貼圖若有，上限 512×512，並啟用 Basis Universal。

## 15. 變現

### 期待值校準

CrazyGames 未公開分潤比例，月結、餘額需達 €100 門檻，累積 5 萬次遊玩才有 SDK 技術支援。solo 開發的恐怖小品第一年廣告收入很可能在數百歐元量級。

**這個專案的真正回報是免費的大規模留存數據**——Basic Launch 的兩週軟啟動會提供自己找不到的真實玩家行為資料。

### 激勵廣告的取捨（待決）

| 選項 | 收入 | 對恐怖的傷害 |
| --- | --- | --- |
| 只做插頁 | 最低 | 零 |
| 激勵廣告綁非核心（外觀、模式解鎖） | 中 | 零 |
| 激勵廣告做復活 | 最高 | 嚴重 |

**建議選項二。** 復活會摧毀死亡的重量——玩家知道死了可以看廣告回來，怪物就不可怕了，等於拿核心資產換廣告收入。

### 插頁位置

每 3～4 次死亡或每完成一整局。**絕不是每次死亡**——局長 20 秒、廣告 30 秒的組合會直接殺死留存。

**F0 的「硬性」是重點。** 三週到期無論完成度如何都拿去測。前置原型是最容易無限延長的地方，而做不完、出不了貨才是這個專案的主要威脅。寧可測一個醜的單門版本，也不要花六週做一個漂亮但未經驗證的東西。

## 17. F0 規格與驗收

### 範圍

```text
場景     靜態走廊 + 一扇門（無奔跑階段）
提示     開場閃示 1 秒的顏色序列
門鎖     4 針、1 假針
上方     工具 + 鎖芯 + 剪影怪物（不做手）
操作     下方拖曳撬鎖 / 按住向下拖曳 = 回頭
計時     隱藏 20 秒、等速型、不做曲線隨機
成功     鎖芯轉滿 → 切黑 → 重來
失敗     切黑 + 一句原因
```

**F0 明確排除：** 奔跑階段、側頭、門邊殘缺提示、曲線隨機、能力拾取、多扇門、雙手、暗角升壓。

### 驗收標準

| # | 問題 | 通過標準 | 權重 |
| --- | --- | --- | --- |
| 1 | 玩家會主動回頭嗎 | 8 成玩家第一局內至少一次 | **必須通過** |
| 2 | 死亡時知道原因嗎 | 8 成能說出自己為什麼死 | **必須通過** |
| 3 | 假針能被識破嗎 | 5 成玩家 3 局內自行發現鎖芯線索 | 可調整 |
| 4 | 回頭之後會猶豫嗎 | 觀察：第二次回頭的間隔變長 | 加分 |

**1 和 2 沒過就是方向不成立**，不要靠加素材硬救。3 沒過表示回饋強度要調。

### 測試方法

找 5～8 個沒看過設計文件的人，錄螢幕，玩三局，事後問「你剛剛為什麼死」。**不要問他們覺得好不好玩。**

## 18. 正式設計原則

1. 玩家一進來就在 gameplay 裡，沒有過場、沒有教學畫面。
2. 怪物是計時器的唯一顯示，因此它的移動必須誠實——禁止橡皮筋。
3. 所有觀察都是免費的；唯一的成本是時間繼續流逝。
4. 提示能加速解題，但漏看提示不等於必死；目標倍率 1:2。
5. 每種門鎖狀態都必須能靠視覺推理，聲音只是加速器。
6. 下方給感覺，上方給事實；上下同步是機械需求，不是美術訴求。
7. 難度優先來自規則變化，其次才是時間壓縮。
8. 恐懼來自玩家自己按下回頭，不來自彈出式驚嚇。
9. 結算只點名一個失敗原因，不列清單。
10. 先驗證核心，再擴充內容；F0 的時程是硬上限。

## 19. 已否決的方向（附理由）

| 方向 | 否決理由 |
| --- | --- |
| 觀看地圖、規劃逃生路線 | 玩家測試顯示未轉化為緊張或樂趣（v1 已否決） |

| 玩家維持張力（雙拇指） | 對休閒受眾的協調門檻過高 |
| 回頭付出撞針代價 | 已改為隱藏計時器；免費回頭＋隱藏時間即可維持張力 |
| 可見倒數 UI | 會使回頭失去唯一的資訊價值 |
| 聲音／節奏鎖 | Web Audio 延遲 80～150ms，且需完整視覺替代版本 |
| 轉珠符文鎖、線路接通鎖 | 方形盤面不適配 16:9 的寬扁操作區 |
| 旋轉密碼鎖作為第二種鎖 | 本質仍是序列記憶，與撬鎖體感重疊 |
| 「接近正確」回饋層級 | 撞針鎖是離散狀態，無「接近」語意 |
| 五扇門 | 死亡損失過重（150 秒），且第 5 門最易死 |

| 一秒分岔路線 | 與找提示、撿能力搶同一個三秒預算，且手勢衝突 |
| 彈出式 jump scare | 稀釋「回頭發現牠很近」這個更好的驚嚇來源 |
| 激勵廣告復活 | 摧毀死亡的重量，等於拿核心資產換廣告收入 |
| 為 Steam 預先增加功能 | 規模不符；只保留架構分層，不做功能 |

## 21. 最終核心

v1 要證明的是「低頭解鎖 vs 回頭確認」的取捨是否有張力。v2 把那個取捨拿掉了，改成證明另一件事：

> **當玩家不知道還剩多少時間，而唯一的知道方式是回頭直視那個正在逼近的東西——他會不會看？看了之後會不會後悔？**

只要玩家在解鎖時反覆猶豫要不要回頭，回頭之後慌忙轉回門鎖，並在最後一秒關上門時產生釋放感，這個方向就成立了。
